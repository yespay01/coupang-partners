# CTR P2 일일 진단·개선 후보 작업 기록

> 기준일: 2026-08-25
> 상태: 로컬 구현·정적/자동 테스트 완료, 운영 반영 전

## 목적

P1에서 수집하기 시작한 노출·쿠팡 이동 이벤트를 KST 일자별로 다시 계산하고, 매일 데이터 품질 문제와 다음 개선 실험 후보를 사람이 검토할 수 있게 만든다.

이 단계는 화면·문구·상품 순서·링크 목적지를 자동으로 바꾸지 않는다. 쿠팡으로 이동하는 실제 링크는 기존 `affiliate_links`와 `/go/{link_id}` 검증 경로만 사용한다.

## 측정 계약

Primary는 Qualified Unique Outbound CTR이다.

```text
분모 = 봇이 아닌 세션 중 product_card_impression 또는 cta_impression이 있는 고유 세션
분자 = 위 분모와 outbound_click 세션의 교집합
CTR = 분자 / 분모 × 100
```

- 동일 세션의 반복 노출과 반복 클릭은 각각 한 번만 센다.
- 봇 이벤트는 분모·분자에서 제외한다.
- 동일 이벤트 ID 재전송은 원본 이벤트를 없애지 않고 품질 신호로 표시한다.
- 노출 없이 발생한 outbound는 `orphan_outbound_sessions`로 따로 표시한다.
- 이벤트가 없으면 성과 0이 아닌 `no_data`로 처리한다.
- 당일 값은 `partial`, 지난 사업일의 수집값은 `complete`로 구분한다.

현재 rollup은 전체 서비스 overall 1행/일이다. 홈·리뷰 상세·검색 등 surface별 원인 분석은 아직 할 수 없으며, 후보에도 `surfaceAvailability: not_available`로 남긴다.

## 구현 범위

### 일별 집계와 진단

- `daily_metric_rollups`: KST 사업일별 적격 세션, 이동 세션, CTR, 품질 수치
- `metric_anomalies`: 무데이터, orphan, 봇, 중복 재전송 이상
- `job_runs`: 날짜별 실행 상태·시도 횟수·오류
- PostgreSQL advisory lock, transaction, upsert를 사용한 재실행 안전성
- 수동 재계산은 한 번에 최대 7일

### 개선 후보

- `improvement_candidates`: 근거, 표본, Primary, guardrail, rollback, 위험 저장
- 상태는 `proposed`, `approved`, `rejected`, `expired`
- 14개 complete 일자와 최소 표본이 없으면 승패 판단 금지
- EPC와 취소율이 없으면 UX 후보의 승인 차단
- DB CHECK로 `winner_declared = false`, `requires_human_approval = true`, `automatic_change_allowed = false` 고정
- 같은 후보 key의 새 제안은 과거 `proposed`만 만료시키며 검토 이력은 보존

### 운영 진입점

- `CTR_DAILY_DIAGNOSTICS_ENABLED=false`가 기본값
- `true`일 때만 매일 04:20 KST에 최근 7일 rollup을 재계산하고 전일 후보를 생성
- 관리자 조회: `GET /api/admin/analytics/optimization?dateRange=30d`
- 관리자 화면은 읽기 전용이며 승인·거절·적용 버튼이 없다.
- 기존 분석 API가 정상이라면 최적화 API 실패만으로 전체 분석 화면을 깨뜨리지 않는다.

04:20 실행은 내부 이벤트 진단만을 위한 현재 구현 시각이다. 설계서의 16:30 쿠팡 리포트 재수집과 16:40~17:10 수익 진단 체계는 아직 연결하지 않았다.

## DB 적용 순서

운영 반영 시 아래 migration을 검토 후 순서대로 적용한다.

1. `automation-server/db/migrate-affiliate-links.sql`
2. `automation-server/db/migrate-daily-analytics.sql`
3. `automation-server/db/migrate-improvement-candidates.sql`

이 작업에서는 운영 DB migration을 실행하지 않았다.

## 검증 항목

- 중복 이벤트 재전송 시 ingest 응답과 품질 플래그
- Qualified CTR이 100%를 넘지 않는 교집합 계약
- KST 날짜 경계와 최근 7일 범위
- rollup/이상/job upsert와 advisory lock
- no-data, partial, 표본 부족, 품질 이상, CTR 하락, 기준선 준비 후보
- 후보 상태 전이와 자동 변경 금지
- 관리자 API DTO와 읽기 전용 화면 타입/빌드
- DB를 쓰지 않는 fixture 기반 후보 CLI

최종 로컬 검증 결과:

- Automation Server `npm test`: 11개 테스트 파일 통과, 실패 0
- 변경 JavaScript 전체 `node --check`: 통과
- 후보 fixture dry-run: 후보 1건, 자동 변경 0건, 승자 선언 없음
- P2 관리자 화면 대상 ESLint: 경고·오류 0
- P2 대상 `git diff --check`: 통과
- 전체 Web TypeScript 검사는 기존 리뷰 편집기·설정 타입 오류 때문에 실패했으며 P2 대상 파일에서는 ESLint 오류가 발견되지 않음
- Web 프로덕션 빌드는 제한된 네트워크에서 외부 리소스 재시도 후 완료하지 못함

## 운영 반영 전 남은 일

- 운영 DB 백업·migration·rollback 절차 승인
- `ANALYTICS_HASH_SECRET`과 제휴 Partner ID 운영값 확인
- `/go/{link_id}` 전체 노출 링크 백필 dry-run 결과 승인
- 쿠팡 최근 7일 리포트 upsert와 클릭·주문·취소·수익·EPC 결합
- surface/device/source 차원 rollup
- 실제 실험 안정 배정, SRM, 신뢰 구간과 사람 승인 실행 흐름
- Slack 일일 보고와 실패 재시도/경보
- 가격 이력 신뢰도 검증 후 가격 하락 알림 별도 구현

배포, 운영 DB 변경, Slack 전송, 자동 UI/콘텐츠 변경은 수행하지 않았다.
