# CTR P1 중앙 링크·측정 기반 작업 기록

> 작업일: 2026-08-25
> 범위: 로컬 구현과 통합 검증
> 운영 DB 변경·백필·배포·커밋: 미실행

## 결과

사용자가 쿠팡으로 이동하는 신규 공개 경로를 UUID 기반 `/go/{linkId}`로 통일했다. 서버는 클릭할 때마다 registry의 활성 상태, 검증 상태, 허용 hostname, 설정된 Partner ID와 목적지의 `lptag`를 다시 확인한다. 브라우저는 원본 목적지를 조립하거나 제휴 ID를 수정하지 않는다.

CTR의 분모와 분자를 같은 세션·페이지뷰로 연결하기 위한 원천 이벤트도 추가했다. 이 단계는 일일 보고서나 자동 승격 자체가 아니라, 이후 진단이 신뢰할 수 있는 데이터를 만들기 위한 기반이다.

## 중앙 제휴 링크

- `affiliate_links`에 UUID `link_id`, 권위 있는 목적지와 fingerprint, Partner ID, `subId`, 출처, 검증·활성 상태를 저장한다.
- 동일 목적지는 fingerprint unique upsert로 같은 `link_id`를 재사용한다.
- 공개 DTO는 `affiliateLink: { linkId, goUrl }` 형태다.
- 프론트는 `goUrl`을 신뢰하지 않고 same-origin `/go/{linkId}`를 구성한다.
- `/api/go/{linkId}`는 미등록·비활성·Partner ID 불일치·허용하지 않은 목적지를 fail-closed로 차단한다.
- 목적지 검증 뒤 클릭 기록 실패는 이동을 막지 않는다.
- 봇 클릭은 새 이벤트에 `is_bot=true`로 남기되 기존 `coupang_clicks` CTR에는 넣지 않는다.
- iframe 다이나믹 배너는 `/go`로 측정할 수 없어 feature flag 기본 OFF로 바꿨다.

## 측정 계약

- 공개 이벤트: `page_view`, `list_view`, `product_card_impression`, `cta_impression`
- 서버 전용 이벤트: `outbound_click`
- 카드·CTA 노출: 화면 50% 이상이 1초 지속될 때 컴포넌트당 1회
- 식별: 1년 익명 UUID와 활동 기준 30분 세션 UUID를 HttpOnly cookie로 관리
- 저장: 익명·세션 원문 대신 서버 HMAC만 저장
- 이벤트 UUID PK와 `ON CONFLICT DO NOTHING`으로 재전송 중복 제거
- KST 기준 `business_date_kst` 저장
- raw IP와 전체 referrer/query는 새 이벤트 테이블에 저장하지 않음
- 원본 브라우저 User-Agent를 내부 프록시로 전달해 봇·기기를 판정
- 한글 slug와 점이 포함된 유입 도메인을 잃지 않도록 제한된 text 필드를 별도로 검증

적용 surface는 홈, 신규 상세, legacy 상세, 검색, 레시피다. `linkId`가 아직 없는 기존 콘텐츠만 기존 `/api/track/click`과 원본 URL fallback을 사용하며, 운영 반영 전 백필 대상으로 본다.

공개 API의 기존 `affiliateUrl`·`productUrl` 필드는 호환을 위해 아직 남아 있다. 다만 `linkId`가 있는 공개 화면은 이 값을 href나 `/go` 입력으로 사용하지 않는다. 원본 필드 완전 제거는 백필 커버리지와 관리자 소비처를 확인한 뒤 별도 계약 변경으로 진행한다.

## 기존 콘텐츠 감사

`scripts/audit-review-content.js`는 JSON 또는 PostgreSQL `READ ONLY` 입력에서 기존 리뷰를 검사한다.

- 허위 구매·사용·배송·포장 경험
- 내돈내산
- 근거 없는 최저가·할인·배송·재고·효능·별점
- 상품명 핵심 단어 누락과 상품-본문 의미 불일치 후보

결과는 위험 점수·등급·사유·근거를 JSON/CSV로만 내보낸다. 게시 상태, 콘텐츠, `noindex`, 삭제를 자동 변경하지 않으며 모든 결과의 `automatedAction`은 `none`이다. 자세한 사용법은 [운영 콘텐츠 감사 도구](../운영-콘텐츠-감사-도구.md)에 있다.

## 안전한 백필

- `npm run backfill:affiliate-links`: 기본 dry-run, SELECT와 URL 검증만 수행
- `npm run backfill:affiliate-links:apply`: 명시적으로 승인한 경우에만 transaction 안에서 INSERT·UPDATE
- 검증할 수 없는 legacy 단축 URL은 자동 등록하지 않음

이번 작업에서는 두 명령 모두 운영 DB에 실행하지 않았다.

## 검증 결과

- Automation Server `npm test`: 7개 테스트 파일 통과, 실패 0
- Automation Server 전체 JS `node --check`: 통과
- 콘텐츠 감사 fixture: 4건 처리, 사람 검수 후보 3건, JSON·CSV 생성, 자동 변경 0건
- Next.js 15.5.7 프로덕션 빌드: 성공, 64개 페이지·라우트 생성
- P1 대상 ESLint: 오류 0, 기존 `<img>` 최적화 경고 3
- 신규·핵심 파일 `git diff --check`: 통과
- 전체 독립 TypeScript 검사는 기존 관리자·설정 타입 계약 오류가 남아 있어 완료 기준에서 제외

첫 Webpack 시도는 외부 리소스 재시도 중 실패 요약만 남겼고, 같은 깨끗한 복사본의 재실행은 컴파일과 64개 라우트 생성을 모두 완료했다.

## 운영 반영 전 필수 확인

1. DB 백업 후 `db/migrate-affiliate-links.sql` 검토·적용
2. 32자 이상의 독립 `ANALYTICS_HASH_SECRET` 설정
3. 웹의 `NEXT_PUBLIC_COUPANG_PARTNER_ID`와 관리자 Partner ID 일치 확인
4. 개인정보 처리방침에 HttpOnly 익명·세션 분석 cookie, 목적, 보존기간 반영 여부 검토
5. 백필 dry-run 보고서와 legacy 단축 URL 수동 검수
6. 승인 후 백필 apply
7. 실제 홈·검색·레시피·상세에서 `/go` 응답과 쿠팡 리포트 채널 귀속 확인
8. 봇 제외, 중복 제거, 한글 slug, 추적 장애 시 302 fail-open을 운영 로그로 점검
9. 자동 실험 승격 전 분석 endpoint에 인프라 rate limit 또는 웹-서버 간 서명 검증을 추가해 위조 이벤트 내성을 높임
