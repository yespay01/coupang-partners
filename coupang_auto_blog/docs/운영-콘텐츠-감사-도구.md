# 기존 리뷰 콘텐츠 감사 도구

> 목적: 기존 리뷰에서 신뢰·정책 위험이 있는 문장을 찾아 사람이 검수할 후보 목록을 만든다.
>
> 안전 원칙: 이 도구는 리뷰 상태, `noindex`, 게시 여부, 콘텐츠를 변경하지 않는다.

관련 설계: [CTR·상품 큐레이션·자동 개선 설계서](./plans/CTR-상품큐레이션-자동개선-설계서_2026-08-25.md)의 17.1절.

## 감사 범위

각 리뷰의 제목과 본문에 0~100점의 `riskScore`, `riskLevel`, `reasons`를 부여한다.

- 실제 구매·사용·섭취·착용을 암시하는 1인칭 체험
- `내돈내산`
- 배송 속도와 포장 상태 체험
- 근거 없는 최저가·가격 우위·할인·쿠폰
- 확인되지 않은 로켓배송·무료배송·재고·품절
- 건강·치료·예방·효능 주장
- 출처 없는 별점과 후기 수
- 상품명 핵심 단어가 본문에 없는 경우
- 상품과 본문의 의미 영역이 다른 경우

상품-본문 불일치는 단순 규칙 기반 휴리스틱이다. 확정 오류가 아니라 우선 검수 후보이며, 카테고리가 잘못 저장됐거나 한 상품이 여러 용도로 쓰이는 경우 오탐할 수 있다.

## 위험도

| 점수 | 등급 | 의미 |
|---:|---|---|
| 70~100 | `critical` | 여러 고위험 주장이 겹친 우선 검수 후보 |
| 45~69 | `high` | 고위험 주장 또는 여러 위험 신호 |
| 20~44 | `medium` | 사람 확인이 필요한 위험 신호 |
| 1~19 | `low` | 약한 불일치 신호 |
| 0 | `none` | 현재 규칙에서 신호 없음 |

`manualReviewRequired`는 20점 이상일 때 `true`다. 모든 행의 `automatedAction`은 항상 `none`이며, 보고서 생성만으로 비공개·삭제·`noindex`가 적용되지 않는다.

## JSON 입력으로 실행

`automation-server` 디렉터리에서 실행한다.

```bash
node scripts/audit-review-content.js \
  --input test/fixtures/review-audit-sample.json \
  --output-dir /tmp/semolink-content-audit \
  --format both
```

입력 JSON은 다음 중 하나를 허용한다.

```json
[
  {
    "id": "1",
    "productName": "상품명",
    "category": "생활용품",
    "content": "본문"
  }
]
```

또는 `{ "reviews": [...] }`, `{ "data": [...] }`, `{ "data": { "reviews": [...] } }` 형식이다. DB 컬럼명처럼 `product_name`, `product_id`, `published_at`을 사용해도 정규화한다.

## PostgreSQL 읽기 전용 실행

DB 모드는 환경변수의 연결 문자열만 사용한다. 연결 문자열을 명령행 인자로 넘기거나 보고서에 기록하지 않는다.

```bash
DATABASE_URL='postgres://...' node scripts/audit-review-content.js \
  --database \
  --status published \
  --output-dir /tmp/semolink-content-audit \
  --format both
```

안전 장치:

- `BEGIN READ ONLY` 트랜잭션
- 코드에 고정된 `SELECT ... FROM reviews` 한 건만 실행
- 상태 값은 파라미터 바인딩
- 최대 100,000건 제한
- 출력 폴더 명시 필수
- 동일 이름의 기존 보고서 덮어쓰기 거부
- Access Key, Secret Key, 제휴 URL은 조회하지 않음

DB 모드의 `--status`를 생략하면 모든 상태를 읽는다. 운영 DB 감사 전에는 먼저 JSON 내보내기 표본으로 규칙의 오탐을 확인하는 방식을 권장한다.

## 출력

`--format`은 `json`, `csv`, `both` 중 하나다. 기본값은 `both`다.

- JSON: 메타데이터, 위험도 집계, 리뷰별 상세 사유와 근거 문맥
- CSV: 관리자 검수용 한 행 요약

파일명 예:

```text
review-content-audit-20260825T091500Z.json
review-content-audit-20260825T091500Z.csv
```

CSV는 `=`, `+`, `-`, `@`로 시작하는 셀 앞에 작은따옴표를 붙여 스프레드시트 수식 실행을 방지한다.

JSON의 주요 형태:

```json
{
  "metadata": {
    "readOnly": true,
    "automatedChangesApplied": false,
    "totalReviews": 395,
    "manualReviewCandidates": 213
  },
  "reviews": [
    {
      "id": "10",
      "riskScore": 65,
      "riskLevel": "high",
      "manualReviewRequired": true,
      "automatedAction": "none",
      "reasons": [
        {
          "code": "PRODUCT_CONTENT_DOMAIN_MISMATCH",
          "label": "상품과 본문의 의미 영역이 다를 가능성",
          "score": 35,
          "evidence": ["상품 신호: 식품·음료", "본문 신호: 수납·가구"]
        }
      ]
    }
  ]
}
```

문서의 숫자는 출력 형식 예시이며 실제 운영 집계가 아니다.

## 검수 절차

1. `critical`, `high`, `medium` 순으로 원문과 상품 페이지를 대조한다.
2. 사유의 `evidence`는 탐지 근거일 뿐 사실 확정이 아님을 전제로 확인한다.
3. GSC·네이버 유입과 외부 링크가 있는 URL은 수정·리다이렉트 판단 전에 별도 표시한다.
4. 허위 경험은 사실 기반 선택 정보로 교체할 수 있는지 먼저 판단한다.
5. 비공개, `noindex`, 301, 삭제는 별도 승인 작업으로만 수행하고 URL 매핑과 감사 로그를 남긴다.

## 테스트

```bash
cd automation-server
node --test test/contentAudit.test.js
```

샘플 fixture에는 정상 확인 안내, 허위 체험·효능·할인, 생수-수납함 불일치, 주얼리 클리너-의류 관리 불일치가 포함되어 있다.

## 한계

- 규칙에 없는 새로운 표현은 놓칠 수 있다.
- `최저가`, 배송, 재고 같은 단어가 있어도 출처와 관측 시각이 별도 데이터에 있다면 사람이 근거를 확인해야 한다.
- 상품-본문 의미 일치는 한국어 형태소 분석이나 임베딩이 아닌 제한된 도메인 단어 사전으로 추정한다.
- 이 도구는 검색 유입·외부 링크 데이터를 결합하지 않는다. 실제 기존 URL 처리 결정에는 설계서 17.1의 트래픽·링크 조사 단계가 추가로 필요하다.
