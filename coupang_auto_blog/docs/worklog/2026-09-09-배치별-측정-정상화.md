# 화면·배치별 전환 측정 정상화

> 작업일: 2026-09-09 KST

## 판단 근거

2026-09-08에 관련 상품과 모바일 고정 CTA를 추가했지만, 관리자 분석은 전체 세션 합계만 제공했다. 원천 이벤트에 `surface`와 `position`이 저장되어도 `related`, `product_detail_primary`, `product_detail_sticky`를 따로 비교할 수 없었다.

코드 계약을 추가로 확인한 결과, 관련 상품 카드가 `surface=related`를 전송하지만 프런트 프록시와 백엔드 허용 목록에 `related`가 없어 이벤트가 거부될 수 있는 측정 누락도 확인했다.

## 반영 내용

- 프런트 이벤트 타입, 공개 이벤트 프록시, `/go` 클릭 프록시, 백엔드 검증 목록에 `related`를 추가했다.
- 선택한 1~31일 기간의 원천 `analytics_events`를 `surface + position`으로 집계한다.
- 봇이 아닌 세션만 사용하고, 같은 화면·배치의 노출 세션과 클릭 세션의 교집합을 적격 이동으로 계산한다.
- 노출 없이 발생한 배치별 클릭은 고아 이동으로 따로 표시한다.
- 관리자 `세션 기준 전환 분석`에 화면·배치별 유효 노출, 적격 이동, CTR, 고아 이동, 관측 기간을 표시한다.
- 배치별 유효 노출이 100 세션 미만이면 표본 부족으로 표시해 성과 승자 확정을 막는다.

별도 DB 마이그레이션은 필요 없다. 배포 후 기존 원천 이벤트에 즉시 적용되며, `related` 데이터는 허용 목록 수정 후부터 정상 누적된다.

## 검증

- Automation Server 전체 테스트 16개 통과
- Next.js production build 통과
- 추가된 배치별 집계의 동일 `surface + position + session` 교차, 봇 제외, 100% CTR 상한 테스트 통과
- 전체 `tsc --noEmit`는 기존 리뷰 편집기·설정 타입 불일치로 실패했으나, 이번에 발견된 `related` 타입 누락은 해결했다.

## 배포 후 확인

1. 관리자 분석에 `관련 상품` 배치가 노출되는지 확인한다.
2. `상세 본문 CTA`와 `모바일 고정 CTA`의 유효 노출과 고아 이동을 먼저 비교한다.
3. 배치별 100 세션 이상이 누적되기 전에는 CTR 차이로 승자를 확정하지 않는다.
