## 3. 사용자 검색을 상품 추가로 연결하는 방식

1. 공개 `/search`의 정상 상품 검색어만 `product_search_demand`에 KST 일별 숫자로 누적한다.
2. URL·이메일·전화번호 형태는 저장하지 않는다.
3. 14일간 2회 이상 검색된 키워드만 인기 수요로 승격한다.
4. 첫 검색부터 화면에 표시된 정상 상품 결과 전체를 해당 검색 응답 그대로 카탈로그에 저장한다. 추가 API 호출은 하지 않는다.
5. 상품별 `search_demand_count`와 `last_user_searched_at`을 기록해 가격 추적 우선순위로 사용한다.
6. 동시에 실제 가격 관측값과 검증된 `/go/{linkId}`를 저장한다.
7. 같은 검색어·같은 결과 수는 5분간 캐시해 Search 호출을 줄인다.
8. 쿠팡 실시간 Search가 제한되면 보유 카탈로그의 최근 실제 관측 가격으로 자동 전환한다.

## 4. API 호출량 보호

- 쿠팡 파트너스 공식 가이드 기준: Search 시간당 최대 10회, Report 시간당 최대 50회, 그 외 API 시간당 최대 100회다.
- 1회 위반 시 24시간 API 호출 차단, 3회 위반 시 파트너스 기능 제한 절차가 안내돼 있다.
- 상품 발굴: 17:50 KST, 목록형 API를 포함해 최대 약 12호출
- Search 가격 보완: 매시간 `:10` KST, 회당 최대 4호출
- Search 보완 슬롯의 절반은 최근 30일 사용자 검색·최근 14일 쿠팡 이동 클릭 상품에 우선 배정한다.
- 나머지 절반은 미관측 상품부터 가장 오래 관측되지 않은 순서로 전체 카탈로그를 순환한다.
- 쿠팡이 `사용 횟수 초과`를 반환하면 해당 작업의 남은 호출을 즉시 중단한다.
- 응답의 재시도 시각을 공통 쿨다운으로 등록해 모든 Search 호출을 막고, 시각 경과 후 자동 재개한다.
- 공개 검색은 사용자가 실제로 검색할 때만 Product API를 호출하며 5분 캐시를 사용한다.

## 5. 전체 가격 추적 원칙

`전체 상품 추적`은 모든 상품을 매일 Search API로 1건씩 호출한다는 뜻이 아니다. 보유한 모든 상품을 추적 대상 큐에 넣고 다음 경로를 합쳐 실제 가격을 확보한다.

1. 카테고리 베스트: 호출당 최대 100개 응답 중 이미 보유한 모든 상품을 묶음 갱신한다.
2. 골드박스: 한 번의 응답에 포함된 기존 상품을 모두 묶음 갱신한다.
3. 쿠팡 PL: 브랜드별 호출당 최대 100개 응답 중 기존 상품을 모두 묶음 갱신한다.
4. 키워드·검색 수요 수집: 검색 응답에 다시 등장한 기존 상품을 모두 갱신한다.
5. 사용자 공개 검색: 화면에 나온 상품 가격을 즉시 기록한다.
6. 위 목록에서 빠진 장기 상품: Search 보완 작업에서 검색·클릭 우선과 전체 순환을 1:1로 배분한다.

가격은 쿠팡 API 응답에서 같은 `productId`가 확인된 값만 기록한다. 응답에 없는 상품의 가격은 추정·복사·보간하지 않는다. 당일 같은 상품은 KST 일자별 upsert로 한 점만 유지한다.

## 6. 가격 검색 표현 기준

- 검색 페이지 제목: `쿠팡 상품 가격 검색`
- 검색 설명은 실제 검색 결과의 가격과 판매 조건을 비교한다는 범위로 제한한다.
- 결과는 Product API가 반환한 검색 결과 안에서만 낮은 가격순으로 정렬한다.
- `최저가`를 보장하는 문구는 사용하지 않는다. 옵션·배송비를 포함한 최종 판매 조건은 쿠팡에서 확인한다.
