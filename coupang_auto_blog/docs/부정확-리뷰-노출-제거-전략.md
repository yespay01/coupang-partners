# 부정확 리뷰 노출 제거 전략

작성일: 2026-08-28  
범위: 공개 홈, 상품 가이드 목록, 리뷰 상세, 레거시 URL, 검색 색인, 가격 표시  
이번 작업: 코드와 운영 DB를 변경하지 않은 읽기 전용 점검 및 실행 기준 문서화

## 결론

현재 공개 여부의 유일한 기준은 사실 검증 결과가 아니라 `reviews.status = 'published'`다. 홈은 리뷰 본문을 직접 링크하지 않도록 바뀌었지만, `/reviews` 목록, 상세 URL, 사이트맵과 메타데이터를 통해 부정확한 본문이 계속 사용자와 검색엔진에 노출될 수 있다.

단기 조치는 **확인된 부정확 리뷰를 `needs_revision`으로 격리하고 공개 목록·상세·사이트맵에서 동시에 제외**하는 것이다. 단, 규칙 기반 감사 점수만으로 자동 비공개하면 안 된다. 담당자가 원문, 상품, 이미지, 쿠팡 도착 URL을 확인해 격리 대상을 승인해야 한다.

장기적으로는 상품 카드 공개 조건과 콘텐츠 검색 색인 조건을 분리해야 한다. 리뷰 본문이 부정확해도 상품명·이미지·중앙 제휴 링크의 동일성이 검증됐다면 홈의 상품 카드와 쿠팡 CTA는 유지할 수 있지만, 부정확 본문과 검색용 `Article` 데이터는 노출하지 않아야 한다.

## 현재 노출 경로 점검

| 경로 | 현재 동작 | 위험 |
|---|---|---|
| 홈 `/` | `/api/reviews?limit=100`의 `published` 행을 상품 카드로 사용한다. 현재 카드는 리뷰 상세 링크 없이 쿠팡 CTA만 제공한다. | 본문은 숨겨도 잘못된 상품명·이미지·가격·쿠팡 도착 상품 조합은 카드에 남을 수 있다. `published`를 상품 검증으로 오인한다. |
| 상품 모음 `/reviews` | 같은 공개 리뷰 API를 사용하고 카드에서 본문 앞부분을 그대로 발췌해 `/reviews/{slug}` 또는 `/review/{id}`로 연결한다. | 허위 체험·배송·할인·효능 문구가 목록 발췌 단계부터 노출된다. |
| 상세 `/reviews/{slug}` | `published`이면 본문 전체를 렌더링하고, 본문에서 description을 만들며 `Article` JSON-LD를 출력한다. | 부정확 문구가 화면, 검색 스니펫 후보, 소셜 미리보기, 구조화 데이터 설명에 동시에 복제된다. 별도 `noindex` 판정이 없다. |
| 레거시 `/review/{id}` | 공개 리뷰를 읽어 slug가 있으면 영구 이동하고, 없으면 기존 본문을 렌더링한다. | 이전 링크로도 본문에 접근할 수 있다. 현재 서버 조회 경로가 ID 전용 API와 일치하지 않아 리다이렉트/404가 일관되지 않을 가능성도 있다. |
| `/sitemap.xml` | `published`이며 slug가 있는 모든 리뷰를 포함한다. | 감사 미통과 콘텐츠도 검색엔진에 발견·재방문을 요청한다. |
| `robots.txt` | 공개 경로 전체를 허용한다. | 현재는 `noindex`가 없으므로 모든 상세가 색인 가능하다. 단, 향후 `noindex` URL을 `robots.txt`로 막으면 검색봇이 태그를 읽지 못하므로 차단 규칙으로 해결하면 안 된다. |

## 즉시 숨길 범위

`automation-server/src/services/contentAudit.js`의 결과는 후보 선별에 사용하고, 아래 대상은 사람이 근거를 확인한 즉시 격리한다.

### P0: 확인 즉시 모든 공개 표면에서 격리

- 실제 체험 근거가 없는데 `내돈내산`, 직접 구매·사용·섭취·착용, 배송 도착, 포장 상태를 사실처럼 쓴 본문
- 상품명·대표 이미지·본문·쿠팡 도착 상품 중 하나라도 서로 다른 상품인 경우
- 출처와 적용 범위가 없는 치료·예방·건강 효능 단정
- 쿠팡 도착 URL이 다른 상품, 오류 페이지, 검증 실패 링크로 연결되는 경우
- 개인정보, 저작권 침해 이미지 등 별도 법적 위험이 확인된 경우

P0는 홈 상품 카드, `/reviews` 발췌, 상세 본문, 레거시 상세, 사이트맵, `Article` JSON-LD, OG/Twitter 미리보기에서 모두 제거한다. `noindex`만 추가하고 잘못된 본문을 계속 보여주는 것은 사용자 보호가 아니므로 허용하지 않는다.

### P1: 본문은 즉시 숨기고 사실 정보 대체 가능 여부 검수

- 관측 시각·옵션·출처 없는 `최저가`, 할인율, 쿠폰, 재고, 품절 임박, 로켓·무료·당일배송 단정
- 출처 없는 별점, 후기 수, 판매량, 인기 순위
- 상품과 본문이 일치하지만 일부 허위 체험 문장만 포함된 경우
- 공식 상품 이미지인지 확인되지 않은 생성 이미지나 제3자 이미지를 체험 사진처럼 배치한 경우

상품 동일성과 제휴 링크가 확인되면 제품명, 공식 이미지, 관측 시각이 있는 가격, 선택 기준, 쿠팡 CTA만으로 구성한 **사실 기반 상품 정보 화면**으로 대체할 수 있다. 대체 화면이 준비되기 전에는 기존 본문과 그 발췌를 노출하지 않는다.

### 감사 점수 사용 방식

| 감사 결과 | 운영 큐 | 자동 조치 |
|---|---|---|
| `critical` 70~100 | P0 우선 수동 검수 | 없음 |
| `high` 45~69 | 당일 수동 검수 | 없음 |
| `medium` 20~44 | 노출 문맥과 근거 확인 | 없음 |
| `low` 1~19 | 상품-본문 일치 오탐 점검 | 없음 |
| `none` 0 | 규칙 미탐 가능성을 고려해 표본 검수 | 없음 |

점수만으로 게시 상태를 바꾸지 않는다. 반대로 점수가 낮아도 사람이 명백한 상품 불일치나 위험 주장을 확인하면 P0로 격리한다.

## 기존 URL 처리 기준

| 상황 | HTTP/색인 처리 | 사용자 화면 | 내부 링크·사이트맵 |
|---|---|---|---|
| 본문만 부정확하고 상품·중앙 링크는 정확함 | 우선 `200 + noindex, follow`; 사실 기반 대체 화면 검수 완료 후에만 index 허용 | 기존 본문과 미검증 미디어를 제거하고 상품명, 공식 이미지, 관측 정보, 선택 기준, CTA만 표시 | 검수 중에는 목록·사이트맵 제외. 홈 상품 카드는 별도 상품 검증을 통과한 경우에만 유지 |
| 상품과 본문/이미지/도착 상품이 불일치하며 대체 대상 없음 | 의도적으로 폐기한 URL은 `410 Gone` 권장 | 오류 안내만 표시하고 쿠팡 CTA 제거 | 모든 내부 링크와 사이트맵에서 제거 |
| 존재한 적 없거나 식별할 수 없는 URL | `404 Not Found` | 일반 404 | 포함 금지 |
| 같은 상품의 정확한 후속 URL이 하나 존재함 | 정확한 후속 URL로 `301` 또는 `308` | 후속 상품 정보 화면 | 이전 URL은 사이트맵 제외, 후속 URL만 포함 |
| 관련 상품은 있으나 정확한 1:1 후속 URL이 없음 | 홈·카테고리로 리다이렉트하지 않고 `404/410` | 대체 탐색 링크는 오류 화면에 일반 링크로 제공 가능 | 사이트맵 제외 |
| 검증 완료한 사실 기반 선택 가이드 | `200 + index, follow` | 근거가 있는 정보만 렌더링 | 목록과 사이트맵 포함 가능 |

운영 원칙:

1. `noindex`는 임시 격리 또는 내용 교체 중 URL 보존에 사용한다. 직접 방문자에게 부정확 본문을 보여주는 용도로 쓰지 않는다.
2. `noindex` 페이지를 `robots.txt`에서 차단하지 않는다. 검색봇이 페이지에 접근해야 태그나 `X-Robots-Tag`를 확인할 수 있다.
3. 모든 잘못된 URL을 홈이나 비슷한 카테고리로 일괄 리다이렉트하지 않는다. 정확한 1:1 대체 관계가 있을 때만 영구 리다이렉트한다.
4. 격리된 상세에서는 `Article` JSON-LD, 본문 기반 meta description, 리뷰 미디어 기반 OG 이미지를 제거한다.
5. 사이트맵 포함 기준을 `published`가 아니라 별도의 사람 승인 결과인 `index_eligible`로 분리한다.
6. 상세 페이지는 현재 최대 1시간 재검증 캐시를 사용하므로 상태 변경 직후 on-demand revalidation 또는 해당 경로 캐시 무효화가 필요하다. 그렇지 않으면 격리 후에도 캐시된 본문이 잠시 남을 수 있다.

## 권장 공개 상태 모델

기존 `draft | needs_revision | approved | published` 워크플로와 별도로 공개 표면별 판정을 기록한다.

```text
product_surface_eligible   홈 상품 카드에 사실 상품 정보를 노출할 수 있음
content_public_eligible    상세 화면에 콘텐츠를 노출할 수 있음
index_eligible             검색 색인을 허용할 수 있음
audit_reviewed_at          사람이 마지막으로 근거를 확인한 시각
audit_reason_codes         격리 또는 승인 사유
```

한 개의 `published` 플래그로 상품 노출, 본문 노출, 검색 색인을 모두 결정하지 않는다. 예를 들어 상품과 중앙 링크는 정확하지만 예전 리뷰 본문이 허위 체험인 경우 다음처럼 처리할 수 있다.

```text
product_surface_eligible = true
content_public_eligible  = false
index_eligible           = false
```

스키마가 추가되기 전 단기 격리는 승인된 대상을 `needs_revision`으로 옮기는 방식이 가장 단순하지만, 이 경우 홈 상품 카드도 함께 사라진다는 점을 감수해야 한다.

## 가격과 가격 차트 문구

### 현재 구현에서 확인한 제약

공개 화면에 가격 이력 차트는 아직 없다. `reviews.product_price` 한 값만 사용하며 관측 시각, 상품 옵션, 쿠폰 적용 여부, 배송비, 가격 출처가 공개 DTO에 없다. 따라서 현 데이터로는 가격 추세, 기간 내 최저, 오늘의 가격을 증명할 수 없다.

현재 문구 중 다음은 바꿔야 한다.

| 현재 문구 | 문제 | 권장 문구 |
|---|---|---|
| `쿠팡 판매가 00원` | 현재가인지, 어느 옵션 가격인지 알 수 없음 | 관측 시각이 있으면 `최근 확인 가격 00원 · 8월 28일 07:45 확인`; 없으면 숫자를 숨기고 `쿠팡에서 현재 가격 확인` |
| `오늘의 쿠팡 가격 확인` | 오늘 관측했다는 근거가 없음 | `쿠팡에서 현재 가격 확인` |
| `수집 시점 가격 · 쿠팡에서 변동 가능` | 실제 수집 시각이 없어 사용자가 신선도를 판단할 수 없음 | `가격 확인 시각 미제공 · 쿠팡에서 현재 가격 확인`; 가능하면 가격 숫자도 숨김 |
| `낮은 가격순`/가격대 필터 | 오래된 단일 값으로 순위를 만들 수 있음 | 관측 시각과 동일 옵션이 확보될 때 `최근 확인 가격 낮은순`, `최근 확인 가격대`; 그 전에는 가격 정렬·필터 비노출 |

### 차트 제공 전 데이터 조건

다음을 모두 만족하지 않으면 차트를 렌더링하지 않는다.

- 동일한 `productId`와 동일 옵션 식별자(`vendorItemId` 등)
- 각 점의 `observedAt`, 표시 가격, 통화, 수집 출처
- 쿠폰·회원가·와우 혜택·배송비 포함 여부
- 유효한 관측값 2개 이상과 관측 기간
- 옵션 또는 상품 식별자가 바뀐 시점의 시계열 분리

관측하지 않은 구간에도 같은 가격이 유지됐다고 보이게 선을 보간하지 않는다. 개별 관측점을 우선 표시하며, 긴 데이터 공백은 차트에서 끊어서 표현한다.

### 차트 정확 문구

```text
제목: 최근 관측 가격
설명: 세모링크가 동일 상품·옵션에서 확인한 쿠팡 표시 가격입니다.
툴팁: 8월 28일 07:45 관측 · 15,900원
낮은 값: 관측 기간 내 낮은 가격
높은 값: 관측 기간 내 높은 가격
변화: 직전 관측 대비 1,000원 낮음
표본 부족: 가격 기록 1회 · 추세 판단 불가
빈 상태: 비교할 가격 기록이 아직 충분하지 않습니다.
고지: 관측 시점 사이의 가격은 알 수 없으며, 쿠폰·회원 혜택·배송비·옵션에 따라 결제 가격과 다를 수 있습니다. 구매 전 쿠팡에서 현재 가격을 확인하세요.
```

`최저가`, `역대 최저가`, `오늘 최저`, `가격 인하`, `곧 오를 가격`, `할인 중`은 각각의 비교 범위와 관측 근거를 검증할 수 있기 전까지 사용하지 않는다. `관측 기간 내 낮은 가격`도 선택한 동일 상품·옵션과 정확한 기간을 화면에서 함께 보여줄 때만 사용한다.

## 실행 순서와 완료 조건

### 0~24시간

1. 읽기 전용 감사 보고서를 `published` 대상으로 생성한다.
2. `critical`, `high`와 상품-본문 불일치 후보를 사람이 상품 페이지와 대조한다.
3. P0 승인 대상은 `needs_revision`으로 격리하고 상세 경로 캐시를 무효화한다.
4. `/`, `/reviews`, 상세 URL, 레거시 URL, `/sitemap.xml`, 검색 메타와 구조화 데이터를 각각 확인한다.
5. 격리 URL, 사유, 승인자, 처리 시각, 기존 유입, 후속 URL을 변경 기록에 남긴다.

### 후속 구현

1. 홈 데이터 소스를 리뷰 공개 API에서 검증된 상품 공개 API로 분리한다.
2. `content_public_eligible`과 `index_eligible`을 추가하고 공개 목록·상세·사이트맵이 동일 판정을 사용하게 한다.
3. 검수 중 상세는 부정확 본문 없이 사실 기반 상품 정보 화면과 `noindex`를 제공한다.
4. 404, 410, 정확한 후속 URL 리다이렉트 매핑을 명시적인 테이블로 관리한다.
5. 메타 설명이 기존 본문을 자동 발췌하지 않도록 검증된 요약 필드만 사용한다.
6. 관측 시각과 옵션 식별자가 없는 가격은 숨기고, 가격 이력 계약이 준비된 뒤 차트를 도입한다.

완료 확인은 단순히 DB 상태가 바뀌었는지가 아니라 다음을 모두 만족하는지로 판단한다.

- 부정확 문장이 홈·목록·상세·미리보기·구조화 데이터 어디에도 나타나지 않는다.
- 격리 URL이 사이트맵에 없고, 의도한 HTTP 상태와 robots 메타를 반환한다.
- 잘못된 상세로 향하는 내부 링크가 없다.
- 유지된 상품 CTA는 중앙 제휴 링크 검증과 상품 동일성 검사를 통과한다.
- 가격 문구에는 관측 시각과 범위가 있고, 없으면 현재가나 최저가로 표현하지 않는다.

## 이번 점검에서 하지 않은 작업

- 운영 DB의 리뷰 상태 변경
- 공개 페이지의 `noindex`, 404, 410 적용
- 리다이렉트 또는 사이트맵 변경
- 가격 데이터 수집이나 차트 구현
- Search Console/네이버 서치어드바이저 삭제 요청

위 변경은 감사 결과에 대한 사람 승인, URL별 처리표와 롤백 계획이 준비된 뒤 별도 배포 작업으로 수행한다.
