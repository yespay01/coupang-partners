# 공개 홈 쇼핑몰형 카피·필터 명세

> 작성일: 2026-08-28
>
> 목표: 방문자가 과장 없이 상품 후보를 빠르게 좁히고, 검증된 쿠팡 제휴 링크로 이동하도록 돕는다.
>
> 범위: 카피와 정보구조 제안. 이 문서는 UI·콘텐츠를 자동 변경하지 않는다.

관련 설계: [CTR·상품 큐레이션·자동 개선 설계서](./plans/CTR-상품큐레이션-자동개선-설계서_2026-08-25.md)

## 1. 현재 홈 점검

현재 구현은 [web/app/page.tsx](../web/app/page.tsx)를 기준으로 점검했다.

### 유지할 점

- 첫 제휴 링크보다 앞에 제휴 고지를 한 번만 표시한다.
- 제휴 고지를 상품 카드마다 반복하지 않는다.
- 내부 상세 이동과 쿠팡 직접 CTA를 분리했다.
- 쿠팡 CTA에 공통 추적 링크 컴포넌트를 사용한다.
- `최저가`, 임의 할인율, 임의 별점, 재고 있음, 로켓배송을 표시하지 않는다.
- 홈 메타 설명은 `현재 가격과 구성을 확인`하는 페이지로 표현한다.

### 개선할 점

| 현재 상태 | 문제 | 권장 변경 |
|---|---|---|
| `오늘의 쿠팡 추천템` | 매일 갱신 및 추천 근거가 화면에 없음 | `쿠팡 상품 모아보기`로 변경 |
| 최신 공개 리뷰 100건을 상품 피드로 사용 | 감사 전 리뷰와 잘못된 카테고리가 쇼핑 탐색을 오염시킴 | 검증된 상품 feed를 별도 조회 |
| 리뷰 `media`의 첫 이미지를 카드에 사용 | 스톡·AI 이미지가 실제 상품과 다를 수 있음 | 쿠팡 API 공식 상품 이미지만 사용 |
| 다이나믹 배너가 제목·필터보다 먼저 노출 | 방문자의 탐색 흐름과 자체 측정 분모를 분산 | 기본 OFF 유지, 켤 경우 첫 상품 섹션 아래에서 별도 실험 |
| 모든 카드 position이 `home_card` | 슬롯별 노출·클릭 차이를 분석할 수 없음 | `home_card_01`처럼 실제 슬롯 저장 |
| 카테고리·용도·가격대 필터 없음 | 100개 목록에서 후보를 좁히기 어려움 | 검증된 데이터부터 단계적으로 추가 |
| `곧 새로운 추천템이 올라옵니다` | 추천 및 게시 시점을 보장하지 않음 | `상품 정보를 준비 중입니다`로 변경 |

## 2. 홈의 한 문장 역할

> 필요한 쿠팡 상품 후보를 카테고리와 용도 기준으로 좁히고, 가격·옵션은 쿠팡에서 확인하는 곳

세모링크가 판매자나 인터넷 최저가 비교 서비스인 것처럼 표현하지 않는다. 세모링크는 후보 탐색을 돕고, 최종 가격·옵션·배송 확인은 쿠팡에서 이뤄진다는 역할을 분명히 한다.

## 3. 최종 카피 명세

### 3.1 메타데이터

```text
title: 세모링크 - 쿠팡 상품 모아보기
description: 필요한 상품을 카테고리와 용도별로 좁혀 보고, 가격과 옵션은 쿠팡에서 확인하세요.
```

`추천`, `최저가`, `특가`, `오늘 갱신`, `직접 사용`, `후기`는 근거 데이터가 없는 동안 메타에 넣지 않는다.

### 3.2 제휴 고지

첫 상품 링크 또는 배너보다 앞에 아래 문구를 한 번만 표시한다.

> 이 페이지는 쿠팡 파트너스 활동의 일환으로, 구매 시 일정액의 수수료를 제공받을 수 있습니다.

현재 `AffiliateDisclosure` 문구와 위치는 이 원칙을 충족한다. 고지를 접거나 모바일에서 생략하거나 작은 툴팁으로 바꾸지 않는다.

### 3.3 Hero

```text
eyebrow: 쿠팡 상품 빠르게 찾기
h1: 필요한 상품을 좁혀 보세요
description: 카테고리와 용도를 선택해 후보를 살펴보고, 가격과 옵션은 쿠팡에서 확인할 수 있어요.
```

검색 입력 placeholder:

```text
상품명 검색
```

검색 버튼의 접근 가능한 이름:

```text
상품 검색
```

`오늘의`, `베스트`, `인기`, `추천`은 각각 갱신 시각, 순위 출처, 충분한 내부 표본, 공개된 선정 기준이 마련된 뒤에만 사용한다.

### 3.4 결과 영역

제목과 결과 수:

```text
상품 모아보기
조건에 맞는 상품 24개
```

페이지 단위 주의 문구:

```text
가격·옵션·배송 정보는 쿠팡에서 변경될 수 있습니다.
```

이 문구는 카드마다 반복하지 않고 필터 바로 아래 또는 결과 제목 옆에 한 번 표시한다.

### 3.5 상품 카드

| 요소 | 카피·표시 원칙 |
|---|---|
| 이미지 | 쿠팡 Product API 공식 이미지 |
| 상품명 | API 상품명에서 검색어 덤프만 제거. 구성·용량은 보존 |
| 카테고리 | 정규화·검수 완료된 값만 표시 |
| 관측 가격 | 신선도 계약 구현 전 표시하지 않음 |
| 배송 배지 | 검증된 `isRocket/isFreeShipping`과 관측 시각이 있을 때만 표시 |
| 선택 이유 | 출처와 규칙으로 설명 가능한 경우만 표시 |
| 보조 링크 | `선택 정보 보기` |
| 주 CTA | `쿠팡에서 가격·옵션 확인` |

`상품 정보 보기`보다 `선택 정보 보기`가 내부 페이지의 역할을 명확히 한다. 다만 해당 페이지가 감사 전 AI 체험문인 경우 보조 링크를 노출하지 않고, 사실 기반 가이드로 교체된 콘텐츠만 연결한다.

CTA 하단이나 카드 안에 다음 표현을 넣지 않는다.

- 최저가 확인
- 오늘만 이 가격
- 품절 임박
- 회원 전용 할인가
- 로켓배송 가능
- 직접 써본 추천
- 만족도 4.5
- 판매 1위

### 3.6 빈 상태

필터 결과가 0개일 때:

```text
조건에 맞는 상품이 없습니다.
필터를 줄이거나 전체 상품을 확인해 보세요.
버튼: 필터 초기화
```

상품 feed 자체가 비었을 때:

```text
상품 정보를 준비 중입니다.
잠시 후 다시 확인해 주세요.
```

링크 검증이 실패한 카드에는 비활성 CTA를 남기지 않고 카드 자체를 공개 feed에서 제외한다.

## 4. 홈 정보구조

권장 순서는 다음과 같다.

1. 헤더
2. 제휴 고지 한 줄
3. Hero와 상품명 검색
4. 카테고리·용도·가격대 필터
5. 활성 필터와 결과 수, 전체 초기화
6. 검증된 상품 카드 그리드
7. 선정·데이터 기준 안내
8. 다이나믹 배너 실험 영역 또는 배너 없음
9. 푸터

다이나믹 배너를 사용할 때도 Hero와 첫 상품 후보보다 앞에 두지 않는다. 배너 iframe 클릭은 공통 `/go` 경로로 측정할 수 없으므로 자체 카드와 같은 성과로 합산하지 않는다.

## 5. 필터 정보구조

### 5.1 첫 화면

모바일과 데스크톱 모두 다음 순서로 둔다.

```text
[상품명 검색________________] [검색]

[전체] [생활·세탁] [식품·음료] [주방·정리] [반려동물]

[용도 ▾] [최근 확인 가격대 ▾] [배송 ▾]      [전체 초기화]

활성 필터: [생활·세탁 ×] [1만원 이하 ×]
조건에 맞는 상품 24개
```

모바일에서는 카테고리 chip을 가로 스크롤하고, 상세 필터는 bottom sheet로 연다. 선택한 조건과 초기화 버튼은 sheet를 닫은 뒤에도 보여야 한다.

### 5.2 필터 우선순위와 출시 조건

| 순서 | 필터 | 값 | 필요한 데이터 | 현재 출시 판단 |
|---:|---|---|---|---|
| 1 | 상품명 검색 | 자유 검색 | 정제 상품명 | 가능 |
| 2 | 카테고리 | 4개 집중 영역 + 기타 | 정규화·검수된 category | 데이터 정리 후 가능 |
| 3 | 용도 | 청소, 세탁, 보관, 조리, 반복 구매 등 | 통제된 purpose tag와 근거 | 현재 불가 |
| 4 | 최근 확인 가격대 | 1만원 이하, 1~2만원, 2~3만원, 3만원 이상 | `observed_price`, `observed_at`, 동일 옵션 identity | 현재 불가 |
| 5 | 구성 | 1개, 묶음, 대용량 등 | 검증된 수량·용량 parser | 현재 불가 |
| 6 | 배송 | 로켓, 무료배송 | API 원값 저장과 확인 시각 | 현재 불가 |

데이터가 없는 필터를 disabled 상태로 미리 보여주지 않는다. 해당 필터 자체를 숨기고 데이터 계약이 충족된 뒤 공개한다.

### 5.3 카테고리

초기 공개 분류:

- 전체
- 생활·세탁
- 식품·음료
- 주방·정리
- 반려동물
- 기타

원본 쿠팡 category ID에서 위 분류로 가는 명시적 매핑을 사용한다. AI가 본문에서 추측한 카테고리나 기존 잘못 저장된 리뷰 category는 사용하지 않는다.

카테고리별 공개 조건:

- 공식 상품 이미지 존재
- 상품명 존재
- 활성·검증 완료된 `affiliate_link_id` 존재
- 금지·품질 격리 상태가 아님
- 카테고리 매핑 성공

### 5.4 용도

자유 텍스트 태그를 사용하지 않고 다음처럼 통제된 vocabulary를 사용한다.

```text
cleaning      청소
laundry       세탁
storage       보관·정리
cooking       조리
consumable    반복 구매
pet_food      반려동물 먹거리
pet_hygiene   반려동물 위생
```

각 태그에는 `rule_version`, `assigned_at`, `assignment_source`, `confidence`, 사람 검수 여부를 보존한다. 상품명·카테고리로 입증할 수 없는 용도를 AI가 임의 생성하지 않는다.

### 5.5 최근 확인 가격대

명칭은 `가격대`가 아니라 `최근 확인 가격대`로 표시한다.

```text
1만원 이하
1만원~2만원
2만원~3만원
3만원 이상
```

출시 조건:

- 가격 관측 시각 저장
- 같은 product/vendorItem/option identity 보존
- 24시간 이내 관측값만 필터에 사용
- 오래된 가격은 필터와 카드에서 제외
- 화면에 `08/28 07:45 확인`처럼 시점 표시

`인터넷 최저가`, `쿠팡 최저가`, 할인율은 외부 비교·정가 데이터가 없으므로 표시하지 않는다.

### 5.6 배송

출시 조건:

- Product API의 `isRocket`, `isFreeShipping` 원값 저장
- 마지막 확인 시각 저장
- 동일 옵션 identity 확인
- freshness 기준 이내인 값만 사용

필터 문구:

```text
최근 확인된 로켓배송
최근 확인된 무료배송
```

짧은 chip에는 `로켓배송`을 사용할 수 있지만 필터 상단에 `최근 확인 정보 · 쿠팡에서 변경될 수 있음`을 표시한다.

## 6. 정렬

현재 허용:

- 최근 등록순
- 상품명순

현재 금지:

- 인기순: 적격 세션과 봇 제외 기준선이 부족함
- 판매순: 쿠팡 판매량 데이터 없음
- 추천순: 랭킹 기준 미공개
- 할인율순: 정가·할인율 데이터 없음
- 낮은 가격순: freshness와 동일 옵션 계약 미구현

`최근 많이 확인한 상품`은 최소 14일의 적격 세션 기준선과 최소 표본 공개 기준을 통과한 뒤 추가한다. 내부 관리자·봇·중복 클릭은 제외한다.

## 7. 상품 feed 계약

홈은 장기적으로 `reviews`가 아니라 공개 상품 feed를 사용한다.

필수 필드:

```text
productId
displayName
officialImageUrl
normalizedCategory
purposeTags[]
affiliateLinkId
affiliateValidationStatus
affiliateValidatedAt
observedPrice?        // freshness 충족 시만
priceObservedAt?
isRocket?             // freshness 충족 시만
isFreeShipping?       // freshness 충족 시만
shippingObservedAt?
guideSlug?            // 사실 기반 가이드가 있을 때만
```

공개 feed의 필수 게이트:

```text
affiliateValidationStatus == valid
affiliate link active == true
lptag == configured Partner ID
officialImageUrl present
normalizedCategory present
quality quarantine == false
```

기존 `affiliateUrl` fallback은 호환 경로로만 남기고 쇼핑 홈 신규 카드의 직접 CTA에는 사용하지 않는다. UUID `affiliateLinkId`가 검증된 상품만 노출한다.

## 8. 클릭 구조와 측정

카드의 두 목적을 시각적으로 구분한다.

```text
상품명·이미지·선택 정보 보기 → 세모링크 내부 사실 기반 가이드
주황색 CTA                     → /go/{linkId} → 쿠팡
```

슬롯 추적:

```text
position: home_card_01, home_card_02, ...
surface: home
content_id: 컬렉션 또는 필터 결과 식별자
product_id: 쿠팡 product ID
link_id: 검증된 affiliate link UUID
```

필터 적용 전후 카드 노출 분모가 달라지므로 `list_view`의 `content_id`에 서버가 허용한 필터 조합 ID를 사용한다. 자유 검색어 전체를 분석 이벤트에 저장하지 않는다.

첫 카피 실험은 다음 한 변수만 비교한다.

```text
control: 쿠팡에서 가격·옵션 확인
variant: 쿠팡에서 가격 확인
```

판정 조건:

- 최소 14일
- 변형당 eligible 세션 1,000 이상
- 변형당 고유 클릭 세션 20 이상
- EPC와 취소율 guardrail 연결
- 오류·orphan·봇 비율 악화 없음
- 사람 승인 전 승자 적용 금지

현재 overall rollup에는 surface 분모가 없으므로 홈 실험을 시작하기 전에 surface별 eligible/outbound 집계가 준비돼야 한다.

## 9. 선정 기준 안내

페이지 하단의 접을 수 있는 설명:

```text
상품 모음 기준

쿠팡 상품 API에서 확인된 상품명과 공식 이미지를 사용하며, 검증된 제휴 링크가 있는 상품만 보여드립니다. 가격·옵션·배송 정보는 쿠팡에서 변경될 수 있으므로 이동 후 다시 확인해 주세요.
```

가격·배송을 사이트에 표시하기 시작하면 관측 시각, freshness 기준, 오류 정정 방법을 함께 공개한다.

## 10. 구현 단계

### A. 현재 데이터로 가능한 안전한 홈

1. Hero와 결과 카피 교체
2. 다이나믹 배너를 첫 상품 섹션 아래로 이동하거나 계속 OFF
3. 검증된 `affiliateLinkId` 상품만 직접 CTA 노출
4. 공식 상품 이미지만 사용
5. 상품명 검색 추가
6. 정규화가 끝난 카테고리 chip만 추가
7. 필터 초기화와 0건 빈 상태 추가
8. 슬롯별 position 기록

### B. 데이터 계약 이후

1. 통제된 용도 태그
2. 가격 이력과 최근 확인 가격대
3. 수량·용량 parser와 구성·단위당 가격
4. 배송 원값과 freshness
5. surface별 CTR과 pre-approved 카피 실험

## 11. 수용 기준

- 첫 제휴 링크 전에 고지가 한 번 보인다.
- CTA마다 고지가 반복되지 않는다.
- `최저가`, 허위 체험, 임의 배송·할인·재고·평점 표현이 0건이다.
- 카드 이미지는 공식 상품 이미지와 product ID가 일치한다.
- 직접 CTA는 검증·활성 상태의 UUID 링크만 사용한다.
- 데이터가 없는 필터는 노출되지 않는다.
- 모든 활성 필터는 URL 또는 재현 가능한 상태로 보존된다.
- 필터 0건 상태에서 한 동작으로 전체 초기화할 수 있다.
- 키보드와 스크린리더로 필터 선택·해제가 가능하다.
- 카드·CTA impression과 outbound가 같은 product/link/slot 문맥으로 연결된다.
- 카피 실험은 최소 표본·기간·EPC·취소 guardrail 전에는 승자를 만들지 않는다.
- 홈 변경은 사람 승인과 별도 배포로만 적용된다.
